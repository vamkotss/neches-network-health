# Neches Network Health

[![CI](https://github.com/vamkotss/neches-network-health/actions/workflows/ci.yml/badge.svg)](https://github.com/vamkotss/neches-network-health/actions/workflows/ci.yml)

A synthetic fiber-network telemetry lakehouse built on Databricks and AWS. It ingests device telemetry, cleans it through Bronze, Silver, and Gold layers, and flags connections that are degrading before customers notice.

> **All data in this repository is synthetic.** It is generated by code in this repo. This project is not based on any real company's systems, schemas, or data.

## Planned architecture

`Generator -> S3 landing -> Auto Loader -> Bronze -> Silver -> Gold -> alerts and BI`

## Planned data defects (the pipeline must catch these)

- Duplicate events from device retries
- Events arriving hours late
- One device clock running behind
- A unit change mid-stream (milliwatts to dBm)
- A device that silently stops reporting

## Status

Phase 0 (repo and environment): in progress. See `docs/journal.md` for the build log.

## Stack

Databricks, AWS (S3, IAM, Lambda, Glue, Athena), Python 3.13, uv, pytest, ruff, GitHub Actions.

## Generate the data

```bash
# tiny = 50 devices, dev = 500 devices (about 2 million rows), full = 2,000 devices
PYTHONPATH=src uv run python -m neches.generate --scale dev --out data
```

The same seed always produces byte-identical files. Answer keys are written to
`data/ground_truth/` so the pipeline's results can be graded.
