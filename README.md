# Neches Network Health

[![CI](https://github.com/vamkotss/neches-network-health/actions/workflows/ci.yml/badge.svg)](https://github.com/vamkotss/neches-network-health/actions/workflows/ci.yml)

A synthetic fiber-network telemetry lakehouse built on Databricks and AWS. It ingests device readings, cleans them through Bronze, Silver, and Gold layers, and flags failing devices and outages before customers notice.

> **All data in this repository is synthetic.** It is generated by code in this repo. This project is not based on any real company's systems, schemas, or data.

## Architecture

`Generator -> S3 landing -> Auto Loader -> Bronze -> Silver -> Gold -> quality checks -> scheduled Databricks Job`

- **Bronze:** raw files loaded incrementally with Auto Loader, plus the source file and load time.
- **Silver:** typed timestamps, duplicates removed, units fixed, clock errors corrected.
- **Gold:** degrading devices, outage and silent-device gaps, daily late-arrival summary.
- **Checks:** 8 automated data-quality checks written to a results table; the job fails loudly if one fails.

## Planted data defects and results

The generator plants known problems and writes answer keys, so the pipeline is graded against the truth.

| Defect | What the pipeline did |
|---|---|
| Duplicate events from device retries | 30,189 duplicates removed (matches the key) |
| Events arriving hours late | 80,504 late rows measured per day |
| One device clock running behind | 5 skewed devices detected and corrected |
| Unit change mid-stream (milliwatts to dBm) | 75 devices converted |
| Slowly degrading connections | 15 of 15 found |
| Outages | 108 of 108 found |
| Devices that silently stop reporting | 3 of 3 found |
| False alarms | 0 |

## Stack

Databricks (Unity Catalog, Auto Loader, Delta Lake, Jobs), AWS (S3, IAM), Python 3.13, PySpark, SQL, uv, pytest, ruff, pre-commit (gitleaks), GitHub Actions.

## Repository layout

- `src/neches/` - the synthetic data generator
- `tests/` - generator tests
- `notebooks/` - exploration and grading notebooks
- `pipeline/` - the production job notebooks (bronze, silver, gold, checks)
- `infra/iam/` - the least-privilege IAM policy
- `docs/journal.md` - build log

## Generate the data

```bash
# tiny = 50 devices, dev = 500 devices (about 2 million rows), full = 2,000 devices
PYTHONPATH=src uv run python -m neches.generate --scale dev --out data
```

The same seed always produces byte-identical files. Answer keys are written to
`data/ground_truth/` so the pipeline's results can be graded.
